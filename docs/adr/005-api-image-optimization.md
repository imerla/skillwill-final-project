# ADR-005: API-ის მიერ მოწოდებული სურათების ოპტიმიზაციის შეზღუდვები

## სტატუსი
მიღებულია

## კონტექსტი
პროექტი იყენებს API-ს, რომელიც პროდუქტის სურათებს აბრუნებს ფიქსირებული ზომით — 700×700 პიქსელი, JPEG ფორმატში (დაახლოებით 70 KB).

სურათები გამოიყენება როგორც პროდუქტის დეტალების გვერდზე, ისე კატალოგის ბარათებში. სურათები ხშირად უფრო მცირე ზომის სივრცეში გამოისახება, თუმცა ბრაუზერი მაინც API-ის მიერ მოწოდებულ სრულ სურათის ფაილს ჩამოტვირთავს.

## პრობლემა
სურათის ფაილის ზომა და ეკრანზე მისი გამოსახვის ზომა ერთმანეთისგან განსხვავდება. მაგალითად, პროდუქტის ბარათში სურათი შესაძლოა დაახლოებით 200×200 პიქსელის სივრცეში გამოჩნდეს, თუმცა ბრაუზერმა ჩამოტვირთოს API-ის მიერ მოწოდებული სრული, 700×700 პიქსელის სურათი.

ეს ზრდის ქსელით გადასაცემი მონაცემების მოცულობას და შეიძლება უარყოფითად აისახოს გვერდის ჩატვირთვის დროზე, განსაკუთრებით მობილურ მოწყობილობებსა და ნელი ინტერნეტკავშირის პირობებში.

Frontend-ის მხრიდან API-ის მიერ დაბრუნებული ორიგინალი ფაილის რეალური ზომის შემცირება შეუძლებელია, თუ სერვერი არ გვთავაზობს სურათის სხვადასხვა ზომის ან ფორმატის ვერსიებს.

## განხილული ალტერნატივები
1. API-ის მხარეს სურათების სხვადასხვა ზომის გენერაცია — სერვერმა უნდა უზრუნველყოს სურათების სხვადასხვა ზომის მიწოდება, მაგალითად, ?w=300 პარამეტრის ან შესაბამისი endpoint-ის საშუალებით.
2. Image CDN-ის გამოყენება — Cloudinary-ის ან სხვა მსგავსი სერვისის გამოყენება, რომელიც უზრუნველყოფს სურათების დინამიკურ ზომასა და ფორმატს.
3. ლოკალური სურათების ოპტიმიზაცია — პროექტში არსებული სტატიკური სურათების წინასწარება და ოპტიმიზებული ფორმატებით მიწოდება.

## მიღებული გადაწყვეტილება
ამ პროექტის ფარგლებში შენარჩუნდა API-ის მიერ მოწოდებული სურათების გამოყენება, ხოლო Frontend-ის მხარეს განხორციელდა ისეთი ოპტიმიზაციები, რომლებიც პროექტის კოდით იყო შესაძლებელი:
- სურათებისთვის განისაზღვრა განლაგების პროპორციები, რათა ჩატვირთვისას გვერდის ელემენტები პოზიცია არ შეცვლილიყო;
- ეკრანს ქვემოთ განთავსებული სურათებისთვის გამოყენებულია Lazy Loading;
- object-fit: contain უზრუნველყოფს სურათების პროპორციების შენარჩუნებას და მათთვის გამოყოფილ სივრცეში სწორად გამოსახვას;
- content-visibility: auto და contain-intrinsic-size გამოიყენება კატალოგის გრიდში განლაგების გაუმჯობესებისთვის.

მთავარი სურათის ფაილის ზომის შემცირება ამ ეტაპზე ვერ განხორციელდა, რადგან ამისთვის API-ის მხარეს დამატებითი მხარდაჭერაა საჭირო.

## გადაწყვეტილების მიზეზები
- API-ის კოდის შეცვლა Frontend პროექტის ფარგლებში შეუძლებელია;
- Image CDN-ის გამოყენება მოითხოვს დამატებით კონფიგურაციას და შესაძლოა დამატებით ხარჯებთან იყოს დაკავშირებული;
- ლოკალური ოპტიმიზაცია გამოსადეგია მხოლოდ პროექტში არსებული სტატიკური სურათებისთვის და ვერ გადაჭრის API-დან მიღებული პროდუქტის სურათების ზომის პრობლემას.

## შედეგები და შეზღუდვები
დადებითი შედეგები:
- სურათების ჩატვირთვისას განლაგების ცვლილება შემცირდა;
- ეკრანს ქვემოთ არსებული სურათების ჩატვირთვა გადაიდო საჭირო მომენტამდე;
- სურათების ვიზუალური განლაგება გაუმჯობესდა.
შეზღუდვები:
- API კვლავ აბრუნებს პროდუქტის სურათებს ერთი ფიქსირებული ზომით;
- Lazy Loading ამცირებს საწყის ეტაპზე ჩატვირთული სურათების რაოდენობას, მაგრამ თვითონ სურათის ფაილის ზომას არ ამცირებს;
- სხვადასხვა ეკრანისთვის შესაბამისი ზომის სურათის მიწოდება მომავალში API-ის ან Image CDN-ის მხარეს უნდა განხორციელდეს.

## სამომავლო გაუმჯობესება
რეკომენდებულია API-ის მხარეს სურათების რამდენიმე ზომისა და თანამედროვე ფორმატის მხარდაჭერა. ამ შემთხვევაში Frontend შეძლებს შესაბამისი ზომის სურათის არჩევას და ქსელით გადასაცემი მონაცემების მოცულობის შემცირება.
