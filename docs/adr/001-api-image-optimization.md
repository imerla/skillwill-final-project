# ADR-001: API სურათების შეზღუდვა

## სტატუსი
Accepted

## კონტექსტი
API სერვერი `https://shop-api-kbe6.onrender.com` აბრუნებს პროდუქტის სურათებს ერთ ფიქსირელურ ზომაზე (700×700 JPEG ~70KB).

## პრობლემა
პროდუქტის ბარათის გამოსახვა კატალოგში იწვევს ზედმეტი ბანდლის მოხმარებას, რადგან ბარათზე გამოსახული სურათი ბევრჯერ მეტია, ვიდრე საჭიროა.

## გადაწყვეტა
Frontend-ში გამოვიყენეთ API-დან მიღებული სურათების ზომებისა და ფორმატის შენარჩუნება (`width`, `height`, `aspect-ratio`, `lazy loading`).

## ალტერნატივები
1. **სწორი გადაწყვეტა:** API სერვერზე დაემატოს სურათების ვარიანტების გენერაცია (მაგ. `?w=300&format=webp`)
2. **Image CDN:** გამოიყენებს Cloudinary ან Img6-ს დინამიური ოპტიმიზაციისთვის
3. **ლოკალური ოპტიმიზაცია:** პროდუქტის სურათების წინასწარ დამუშავება და Vercel-ზე გაშვება

## მიზეზები არჩეული გადაწყვეტისთვის
- API სერვერის შეცვლა მოითხოვს დროს და რესურსებს
- Image CDN მოითხოვს დამატებით ხარჯებს
- ლოკალური ოპტიმიზაცია მოითხოვს build time-ს
- ჩვენ სიტუაციაში (5-6 კვირიანი პროექტი) ეს მისაღებია

## შედეგები
- Performance ქულა გაუმჯობესდება CLS ოპტიმიზაციით, მაგრამ სურათების ბანდლის შემცირება არ მოხდა
- მომხმარებლებს მაინც მოუწევთ ზედმეტი ლოდინი ბანდლის გამო
